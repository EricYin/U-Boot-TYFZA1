# 启动、网口和传输再审查

基线为本地 1.6 / 5fbcc44。仅离线验证，没有访问、刷写或重启设备，没有推送 GitHub。

## 确认并修复

### TCP RST 后上传状态一直忙

固定 lwIP `http_err` 在连接被复位或错误移除时只释放 `http_state`，没有走正常关闭路径里的 `httpd_post_finished`。U-Boot 的全局 `post_state.connection` 因而指向已释放的连接，`http_busy()` 持续返回真，后续 POST 被拒绝。浏览器取消、断开、TCP 超时都可能触发错误回调。

修复在释放前通知仍有未完成 POST 数据的连接。实际上传层检查 received/expected，不会把半包当成成功上传，也不会执行未收齐的任务。测试把真实错误回调与真实上传完成、busy 函数连接运行；修复前 owner 中断用例失败，修复后恢复空闲，其他连接的错误不影响当前上传。

### 静态 UBI 内核卷启动失败、动态卷多读填充

`tyfboot` 原来固定 `ubi read ... 0x600000`。当前 UBI 读取器明确拒绝超过卷 used_bytes 的读取，因此保存较短 FIT 的静态卷会直接失败。动态卷 used_bytes 通常包括全部已保留空间，所以可能多读数 MiB 填充，而没有按 FIT 长度校验整个镜像就调用 source。

修复先读取卷大小和 FIT 头，确认 magic、FIT 总长度不少于头部、不超过 used_bytes 和已有的 6 MiB 内核上限，再按实际长度读入 RAM。使用已有生产 FIT 检查后才执行脚本；异常槽位值、读取失败、环境设置失败均返回恢复路径。不推测替换系统槽，也不引入自动机型判断。

边界测试覆盖短静态卷、动态填充、头部损坏、长度溢出、读取失败和校验失败。新增 U-Boot sandbox 集成执行真实 FIT/hash/LZMA 校验、真实环境变量和 Hush/source：两配置和动态卷能够执行指定脚本，损坏、缺配置、无效槽位和读取失败均不执行脚本。只有 UBI 读盘接口被替代，未模拟运行 Linux。

### PHY 全部初始化失败后不能重试

一次失败会将内部端口 maps[].phy_id 改成 -1。若四个口全部失败，is_phyinited 仍为 0，但下一次 start 沿用四个 -1，完全跳过 PHY 探测，故障解除也无法恢复。

修复在尚未成功初始化的每次 start 前恢复固定内部 PHY1–4 映射；外置端口保持禁用。不增加忙轮询或等待时长，不改变 TCP 窗口。测试覆盖缺 PHY、配置、读寄存器和恢复供电写寄存器四类瞬时失败，先失败再清故障重试，能够用 NI3 恢复。

# 本地 1.6 再审查

审查基线：b8d6462。按用户要求仅离线审查、构建和更新本地版本，不同步 GitHub、不刷机或重启。

## 确认的问题

1. **高优先级：2920 字节窗口引入吞吐回归。** `overlay/configs/tyfza1_defconfig` 与 `scripts/prepare.py` 强制两段 TCP 窗口。在 RTT 3 ms 时理论上限不足 1 MB/s，还使当前 lwIP 接收 200 段时的 ACK 数由 100 增至 200。撤回两处覆盖，恢复固定上游配置。以前的“暂停 CPU、整批灌入 FIFO”测试不足以说明真实丢包或最优窗口。
2. **中优先级：启动配置同值保存不落盘。** `boot-config.c` 在新旧值相等时直接返回成功。串口 `setenv tyf_bootconf conf-1` 后网页点击保存，NAND 实际未写。新增两个用例在修复前均失败；删除提前返回后，保存动作总会执行 `env_save`，失败会返回错误。
3. **中优先级：合法未压缩 FIT 设备树可能被误拒绝。** FIT 属性按 4 字节对齐，libfdt 的完整检查要求 8 字节对齐。真实 sandbox 上原校验返回 -19（FDT_ERR_ALIGNMENT），对外报告 -EINVAL。修复为对未压缩且不对齐的 DT 做对齐内存副本。此问题早于本次千兆简化改动，但旧安装测试用桩函数代替 FIT 校验，未覆盖它。

## 审查范围

- 固定 NI0–NI3 与内部 PHY1–4 映射，NI4+禁用；无自动机型分支或外置 2.5G 驱动。
- PHY 10/100/1000 协商与 MAC 速率/双工设置、后插网线、断线重选、状态展示；寄存器行为测试不能替代电气实测。
- 旧自动环境变量清除、显式 Linux 配置、配置保存/失败回滚、启动和恢复分支。
- 两种 boot 模板的签名/不可变内容匹配、歧义拒绝、坏块检查、先 FIP1 后 FIP0 与读回校验。
- FIT configuration 选择、未压缩与 LZMA 设备树、哈希损坏、外部板型和缺失 configuration 的拒绝。
- 前端上传/状态查询、配置保存、PON/LOS 状态灯与 GPIO 归还。

## 新增验证

生产 lwIP 时序模型替代旧的暂停 CPU 容量测试；常规用例包含同值保存的实际 env_save 调用和错误传递。`scripts/test_sandbox_crypto.py` 额外编译生产 FIT 检查代码，使用真实 U-Boot FIT/libfdt/LZMA/hash 实现运行九个用例，保留四个密码校验和十六个串口恢复用例。

未发现其他可在本次审查中确认的回归。该结论有明确边界：没有运行本次固件的真实设备冷启动、协商或上传测速；历史约 1 MB/s 的全部原因仍未确认，不以测试通过承诺“无 bug”。

# TYFZA1 硬件机型识别

1.6 按板上实际存在的外置 PHY 识别机型。启动时先执行原厂外置 PHY 的复位、使能时序，再通过 MDIO 地址 7、Clause 45 PMA/PMD 的寄存器 2 和 3 读取芯片 ID。

| 实际读数 | 机型 | FIT 配置 |
| --- | --- | --- |
| `0x001cc840`，忽略最低 4 位修订号 | RTL8221B，2.5G + 3×GE | `conf-0` |
| `0xffffffff` | 外置 PHY 无响应，全千兆 | `conf-1` |

MDIO 事务超时、全零、部分异常或其他芯片 ID 返回错误，不能当作“无外置 PHY”。错误会打印在串口，保留原有恢复入口。

## 为什么移除 1.5 的识别方法

1.5 用两份原厂 BL2/BL31 的 SHA256 关联机型。这是固件版本指纹，不能独立证明物理机型；读取、解析或匹配失败时，又退回 GPIO113:111。全千兆样本在这些失败条件下，GPIO 为 `000` 仍会被判成 2.5G。原测试甚至接受这种结果。

1.6 删除指纹表及读取 FIP 的识别代码，也删除 GPIO 回退。识别不依赖 NAND 内容、已保存的 `board_variant` 或当前网线协商速度。网页、LAN 映射和 FIT 选择使用同一次硬件识别结果。

安装器对 GPT、BL2、BL31 的匹配是保留每台设备早期固件的独立检查，不是启动时的物理机型判据，仍予保留。

## 时序依据

GPIO128 拉低 30 ms，释放后等待 300 ms；GPIO14 置高再等待 300 ms，然后读取 ID。该序列沿用项目已有 RTL8221B 初始化，提前到板型选择前执行，网络初始化时不再重复复位。

全千兆原厂启动记录明确报告地址 7 无 PHY，随后报告 4 个 GE、0 个 2.5GE。两款原厂备份中的 RTL8221B 模块功能相同；全千兆模块的 `init_module` 反汇编同样显示 GPIO14 置高及 300 ms 等待。两款原厂设备树均包含 GPIO128 外置 PHY 复位配置。

## 验证范围

- `tests/test_board_id.py` 执行实际检测函数、Clause 45 事务和 `board_late_init()`；模拟正常 RTL8221B 各修订号、无器件、过期环境变量、4 个 MDIO 阶段超时及异常 ID，并检查先复位、使能、等待，再读 ID 的顺序。
- `tests/test_ni_board.py` 检查只有 2.5G 版启用 port4/MDIO7 和 S3，网口初始化不重复复位已识别的 PHY。
- 2026-10-28 本地全千兆样机在运行的 OpenWrt 中，通过内核加锁的 `SIOCGMIIREG` 实读地址 7，寄存器 2、3 均为 `0xffff`。未直接并发操作内核正在使用的 MDIO 控制器。
- 全部测试与构建日志保存在本地 1.6 发布记录中。上述运行系统中的只读实测，不等同于新 U-Boot 的冷启动验证。按用户要求，本次未重启或刷写样机；未进行 2.5G 样机的新版本启动验证。

正常供电、MDIO 可访问的两款已知硬件是当前适用范围。全 `1` 表示总线上没有器件响应；如果已安装的外置 PHY 因硬件损坏或未正常供电而完全不响应，它与未安装器件在此接口上不可区分。因此不能把软件测试通过表述为覆盖所有硬件故障和未知板卡修订的 100% 正确率。

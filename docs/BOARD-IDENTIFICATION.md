# TYFZA1 硬件机型识别

1.6 按板上实际存在的外置 PHY 识别机型。本地审查修订后，启动时建立并回读检查 MDIO 和 GPIO 配置，执行原厂外置 PHY 的复位、使能时序，再通过 MDIO 地址 7、Clause 45 PMA/PMD 的寄存器 2 和 3 读取芯片 ID。

| 实际读数 | 机型 | FIT 配置 |
| --- | --- | --- |
| 连续两次相同的 `0x001cc840` 系列 ID（最低 4 位是修订号） | RTL8221B，2.5G + 3×GE | `conf-0` |
| 完整 1 秒发现窗口内每次均为 `0xffffffff` | 外置 PHY 无响应，全千兆 | `conf-1` |

两次采样间隔 10 ms。启动阶段的全零或异常读数允许在窗口内恢复为有效 ID；只有始终全 `1` 才按无外置 PHY 处理。曾读到非全 `1` 的响应，却在截止前无法稳定匹配 RTL8221B，返回错误。MDIO 事务超时或初始化回读失败立即返回错误。错误会打印在串口，保留原有恢复入口。

## 为什么移除 1.5 的识别方法

1.5 用两份原厂 BL2/BL31 的 SHA256 关联机型。这是固件版本指纹，不能独立证明物理机型；读取、解析或匹配失败时，又退回 GPIO113:111。全千兆样本在这些失败条件下，GPIO 为 `000` 仍会被判成 2.5G。原测试甚至接受这种结果。

1.6 删除指纹表及读取 FIP 的识别代码，也删除 GPIO 回退。识别不依赖 NAND 内容、已保存的 `board_variant` 或当前网线协商速度。网页、LAN 映射和 FIT 选择使用同一次硬件识别结果。

安装器对 GPT、BL2、BL31 的匹配是保留每台设备早期固件的独立检查，不是启动时的物理机型判据，仍予保留。

## 时序依据

先设置 `GLOBAL_PIN_MUX_NEW` 的 MDIO enable 位，以及手动 MDIO 模式与 MDC 分频 31。GPIO128 拉低 30 ms，释放后等待 300 ms；GPIO14 置高再等待 300 ms，然后进入 ID 发现窗口。回读检查 GPIO mux、输出方向及输出锁存值。该复位/使能序列沿用项目已有 RTL8221B 初始化，网络初始化时不再重复复位。

寄存器定义来自固定 GPL 基线 `5090fbcb` 的 Taurus `registers.h`：`GLOBAL_PIN_MUX_NEW`（`0xf43200f4`）bit11 为 `iomux_mdio_enable`；`PER_MDIO_CFG` 高 16 位为分频。`common/ne/taurus/aal_phy.c` 和 `aal_phy.h` 的分频公式及 62500 kHz PER 时钟给出 MDC = 62.5 MHz / (2 × 32)，约 0.977 MHz。配置保留其他寄存器位，避免依赖早期固件遗留的分频值。

1 秒发现窗口是有界启动策略，不是已验证的所有 PHY/板卡最坏上电时间保证。正常已响应的 RTL8221B 在连续两次 ID 匹配后即可退出；全千兆机型额外等待完整窗口。

全千兆原厂启动记录明确报告地址 7 无 PHY，随后报告 4 个 GE、0 个 2.5GE。两款原厂备份中的 RTL8221B 模块功能相同；全千兆模块的 `init_module` 反汇编同样显示 GPIO14 置高及 300 ms 等待。两款原厂设备树均包含 GPIO128 外置 PHY 复位配置。

## 验证范围

- `tests/test_board_id.py` 执行实际检测函数、Clause 45 事务和 `board_late_init()`；模拟 RTL8221B 各修订号、无器件、延迟响应、启动时全零、一次响应后消失、变化的 ID、各 MDIO 阶段超时，以及 mux/方向/锁存/分频写入失败。模拟器按 GPIO 实际方向和复用产生引脚状态，只有 MDIO 配置及复位/使能条件满足后才让 PHY 响应。
- `tests/test_ni_board.py` 检查只有 2.5G 版启用 port4/MDIO7 和 S3，网口初始化不重复复位已识别的 PHY。
- 临时副本中的反向验证：故意将 GPIO128/GPIO14 留在输入方向时，8 项识别测试中 5 项失败；故意恢复单次全 `1` 立即定型时，3 项失败。原实现的同类 GPIO 方向变异曾被全部 5 项旧测试漏过。
- 2026-10-28 本地全千兆样机在运行的 OpenWrt 中，通过内核加锁的 `SIOCGMIIREG` 实读地址 7，寄存器 2、3 均为 `0xffff`。未直接并发操作内核正在使用的 MDIO 控制器。
- 全部测试与构建日志保存在本地 1.6 发布记录中。上述运行系统中的只读实测，不等同于新 U-Boot 的冷启动验证。按用户要求，本次未重启或刷写样机；未进行 2.5G 样机的新版本启动验证。

初始本地 1.6（`4f3b1b5`）审查发现：一次全 `1` 被直接判定为全千兆，注入“比采样点晚 1 ms 响应”的条件可误判；把 GPIO 输出方向故意写反时旧测试仍全部通过。本次修订针对这两点，未把它们表述成已测得的实机故障。

正常供电、MDIO 可访问且在发现窗口内响应的两款已知硬件是当前适用范围。全 `1` 表示总线上没有器件响应；如果已安装的外置 PHY 因硬件损坏、线路故障、未正常供电或超过窗口才就绪而完全不响应，它与未安装器件在此接口上不可区分。软件初始化回读和轮询不能证明外部电气连接完好，因此不能承诺覆盖所有硬件故障和未知板卡修订的 100% 正确率。

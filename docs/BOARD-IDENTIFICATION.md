# 千兆恢复与 OpenWrt 启动配置

本地 1.6 修订删除自动机型判断。不会读取 MDIO7 的 ID、GPIO strap 或固件指纹来选择网络端口、灯光、Linux 设备树，也不会因外置 PHY 冷启动慢而把 2.5G 版误认成全千兆版。

## 固定恢复网络

两种硬件的片内 PHY 地址均为 1–4，对应 NI0–NI3。全千兆版四个口均可用；2.5G 版的 NI3 没有外部插座，使用其三个普通千兆口。NI4 及以上不启用。外置 RTL8221B、Clause 45 命令、S3/P4 和其他 SerDes 初始化均不再编译。

内部 PHY 保留 10/100/1000 自动协商，MAC 按实际速率切换 MII/GMII 与双工。页面显示所选链路实际速率，不硬编码为 1000 Mbps。PON/LOS 的 GPIO9/10 为两种原厂设备树共有的低电平有效状态灯。

## Linux 配置

`tyf_bootconf` 仅接受 `conf-1`（全千兆）与 `conf-0`（2.5G），由恢复网页明确选择并保存到冗余环境区。旧自动变量 `board_variant`、`b_conf` 在启动时清除。未选择时 `tyfboot` 返回恢复网页；恢复网络、备份和 U-Boot 更新不依赖 Linux 配置。

系统安装和内存启动使用已选择的 FIT configuration，并验证完整 FIT、镜像哈希、DT 格式和 `tianyi,tyfza1` 兼容标记。正式启动前才把选择写入签名脚本所需的 `b_conf`。选择错误仍会影响 Linux，因此页面明确要求按实际硬件选择；系统不会暗中猜测。

## 引导包兼容检查

通用包仍保留两组原厂 GPT/BL2/BL31 模板，共享相同 BL33。这些模板用于保证更新仅替换可变的 BL33/FIP 内容，不能用于判断物理机型。网页更新逐项验证签名并匹配当前 boot 的 GPT、BL2、BL31、保留字节；必须恰有一个兼容模板。两个都匹配、无匹配或任一损坏都在擦除前拒绝。

保留坏块检查、FIP1 先写、FIP0 后写和逐块读回校验。Linux 安装器同样按本机引导内容匹配，不会设置或推断 Linux 配置。

## 离线验证

`test_boot_config.py` 执行选择、保存失败回滚和晚期启动代码；`test_ni_board.py`、`test_ni_start.py` 执行后插网线、端口切换与单 PHY 故障路径；`test_ni_gigabit.py` 在四端口、三速率、两双工、三组初始寄存器值下对比原厂寄存器行为；`test_restore.py` 对两种原厂 boot 实际执行通用包选择及模拟 MTD 写入。

上述是软件验证，未在本次修订中刷机或重启任何设备。
